# 界面规则（044 v3 起生效）

改界面前先读这页。审查也照这页查；和这页冲突的样式改动，先改这页再改代码。

原型是 [`prototype-044/v3-layered.dc.html`](./prototype-044/v3-layered.dc.html)（用户 2026-11-04 定稿），里面的数字都是示例。
040 的「四层」和 026 的多状态色，凡和 044 v3 冲突的地方以这页为准；颜色变量和对比度的底子仍在
`public/style.css` 的 `:root`，深色是同一组变量的另一套值，另见 [style-guide.html](./style-guide.html)。

## 一、三条规矩

### 1. 一层打开一层

第一层只给一句话 + 几行；点开才是下一层。每一层只回答一个问题。

- **工作台**：一句话现状（「有 3 件事等你拍板，其余 6 件 AI 在自己干。」）+ 四行（等你拍板 / 在跑 / 排队 / 今天完成，各一个数字和一句预览）→ 点一行进那一组的列表，顶上「工作台 › …」→ 点任务，右侧滑出详情 → 详情里过程 / 结果 / 审计默认折着。
- **剧组**：一人一行（名字、`▶ / ‖ / !`、一个状态点）→ 点开就地展开账号槽、擅长、手上的活。
- **记录**：一句话总结 + 三张小卡（做完 / 谁干的 / 花了）→ 按天一行 → 点开那天看每件活 → 再点进详情。
- **设置**：一行一类（接入 / 安全 / 通知 / 外观 / 备份）+ 一句状态，只有要你看的那行亮 → 展开是小开关和一句说明 → 「管理规则」「加渠道」再进一层。

不要在第一层摆图表、额度、审计；不要为了「信息全」把详情摊在卡片正面；不要在列表层再套一层卡片。
地址跟着层走（`/?g=…`、`?task=…`、`/settings/…`），刷新、后退、贴进推送都要落回同一层。

### 2. 墨色 + 一个黄绿色相，只靠饱和度分轻重

整页只有墨色（正文、标题、实心按钮、头像底）和一个黄绿色相。轻重只调深浅：

| 轻重 | 变量 | 用在哪 |
|---|---|---|
| 最饱和 | `--accent` | 要你拍板、当前导航、全站唯一的主按钮 |
| 中间 | `--accent-soft` | 在跑、进行中、次一级强调 |
| 淡 | `--chip` / `--track` / `--line` / `--line-strong` | 排队、完成、离线、表头、未填的额度格 |
| 墨 | `--ink` / `--ink-2` / `--muted` / `--faint` | 标题、正文、次要说明、实心按钮、执行者头像 |

- 不再用橙、红、蓝、绿区分状态；旧页面里那些颜色叫什么不再作为依据。
- 所有执行者头像统一墨色，不一人一色；图表和进度条要用第二档时，也只能取同一黄绿的深浅。
- 高风险、失败、等你拍板要「饱和度 + 符号或文字」一起说，不能只靠颜色。
- 大面积底色保持中性。要把注意力拉过去，用一个小饱和点、一条边、一个按钮，不要把整张卡涂满。
- 荧光黄绿只做填充，不当白底上的字色；要彩色字用 `--accent-ink`。全站唯一的荧光实心按钮是顶部「派出去」；其他主按钮用墨色实心。
- 深色模式只换变量，结构不动；上面的轻重顺序在深色里也要成立。

### 3. 符号能代替的字就不写

- `›`：进下一层，或「还有内容」。
- `+` / `−`：展开 / 收起。
- `▶ n` 在跑、`‖ n` 排队、`! n` 等你：写在剧组一行里（053.1）。
- `✕ n`：没成 / 失败；`—`：没有数据，不写「暂无」。
- 每个符号都带 `title` 和 `aria-label`，读屏听到的是完整说法；符号不能拿颜色单独背书。

该写字的仍然写字：审批的三个去向（批准 / 不行，让它改… / 我自己来）、高风险操作的名字、一句话现状。
符号省的是重复的标签，不是后果。数字必须带口径：`12` 不叫数字，`近 30 天 12 单` 才是；样本少于 5 不给百分比，只给条数。

## 二、三层组件清单

原子 → 分子 → 组织。原子和分子在 `src/views/components.ts`，页面只拼装、不手写它们的样式；
组织是视图函数，取数并拼装，不一定在 `components.ts` 里。同一个对象全站只有一个实现，改一处就全改。

标「还没抽」的项目目前是页面内联；动它之前先按这里的名字抽成原子 / 分子，不要再抄第三份。

### 原子：只做一个小件

| 项 | 函数 | 怎么用 |
|---|---|---|
| 头像 | `avatar(k, size)` | 执行者名字第一个字，墨色圆底；全站统一，没有执行者色。 |
| 阶段点 | `stageDots(k, { noChanges })` | 五个点：领取 / 编码 / 合并 / 推送 / 完成。走过实心，正在走的那一点在跳，跳过是空。 |
| 细进度条 | `progressBar(pct, color)` | 只在有真实百分比时出现；细，不拿它当装饰。 |
| 状态点 | `dot(color)` | 一个小圆点；要「点 + 字」时用 `tag()`，别在页面里自己拼胶囊。 |
| 额度点 | `quotaMeter(accounts)` / `bar(pct, color, true)` | 执行者行和详情里的额度用细条；侧边栏「额度」那十格点还没抽，现在在 `src/views/layout.ts` 的 `quotaRail()` 里直接生成。动它时抽成 `quotaDots()` 再复用。 |

### 分子：一个对象一张脸

| 项 | 函数 | 怎么用 |
|---|---|---|
| 任务卡 | `taskCard(t, opts)` | 全站唯一一种。标题、头像、项目、阶段点、在跑进度条、一句现状、最多一个动作；工作台分组列表、剧组展开、看板都用它。 |
| 审批卡 | `needCard(a, task, opts)` / `approvalCard(a, task, opts)` | 挂在任务上的审批，工作台列表用 `needCard()` 只列一行和 `›`，点进详情才批准（053.2）；详情用 `approvalCard()`，带「不行，让它改…」「我自己来」。无任务的独立审批可在列表操作；`inline` 是显式例外，不代表任务列表可以直接批。 |
| 一行分组 | 还没抽；现在是 `overviewPage()` 和 `settingsHome()` 里的 `.group-row` | 数字 / 符号 + 标题 + 一句预览 + `›`；工作台四行、设置五类共用。第三个页面要用时先抽 `groupRow()`。 |
| 小卡 | `tile(o)` | 标签 + 大数字 + 小图 / 分段条，整张可点。记录页三张卡（做完 / 谁干的 / 花了）现在还是 `data.ts` 的 `.lcard` 内联，下次动它时收回 `tile()`。 |

### 组织：一屏只做拼装

| 项 | 函数（文件） | 拼什么 |
|---|---|---|
| 工作台 | `overviewPage()`（`src/views/overview.ts`） | `needCard()`、`taskCard()`、`runnerNotice()`、`execTag()`、`dot()`、`cardRank()`；第一层只有一句话和四行。 |
| 剧组 | `teamPage()`（`src/views/team.ts`） | `avatar()`、`quotaMeter()`、`taskCard()`、`execHead()`；一人一行，展开才看账号槽和手上的活。 |
| 记录 | `dataPage(q, tab)` / 文件内的 `ledgerPanel(q)`（`src/views/data.ts`） | `dot()`、`bar()`、`empty()` 和结局色阶；一句话 + 三张小卡 + 按天。旧的 `stackedBars()` 只留在没改到的明细里。 |
| 设置 | `settingsHome()` / `settingsPage()`（`src/views/settings.ts`） | `tag()`、`riskBadge()`、`empty()`、`dot()`；一行一类，展开是开关，要填的表单再进一层。 |
| 详情面板 | `taskPanel()`（`src/views/tasks.ts`） | `stageDots()`、`approvalCard()`、`panelHead()`、`statusBadge()`；右侧滑出，过程 / 结果 / 审计先折着。 |

拼装时还要守：

- 页面里不出现手写的原子 / 分子 HTML；缺函数就先抽，不要复制。
- 表单只在抽屉里，或展开后的第二层。第一层不摆空输入框；顶部「让 AI 做什么？」是例外，它本身就是正在做的事。
- 一块最多一个主按钮；动作按状态给一个（排队给「开始」，等审批给「去审批」，失败给「重试」），不适用就不放。
- 地址就是状态：同一个任务不管在哪一页，详情都是 `?task=<id>`；刷新、收藏、后退都能回到原处。

## 三、动效

动效不按数字设计，按使用体感调；不写死时长和曲线，用户上手试过才算。

**参考的感觉**

- 切视图像翻一本薄册子：只换内容区，侧边栏和顶栏不跟着动，不像刷新网页。
- 详情面板像拉出一只抽屉：从右边滑进来，关的时候退回去；不是整页跳走。
- 分组展开像把折着的一角摊开；额度小卡像从侧边栏抽出一张小纸条。
- 批准 / 驳回像在纸上盖章：颜色变、写清批了什么，停一下让人看清，再收起。
- 按钮点下去马上有反应（颜色变、轻轻下沉）；高风险操作的成功态要让人看清自己刚批了什么——038 的这两条意图保留。

**要避免的感觉**

- 弹簧回弹、缩放弹跳、旋转飞入、整页淡入淡出、3D 翻转。极简不是没有手感，是不用花活。
- 同时动很多块、骨架屏闪烁、本地操作还转圈；不要让人等动效。
- 只靠动画表达状态变化；状态必须同时有文字或颜色落下来。
- 为了「有动效」而动效。能用 CSS 做的（`:hover`、`details[open]`、宽度变化）不写 JS。

**减少动态效果是硬规则**：`@media (prefers-reduced-motion: reduce)` 下所有形变和位移都关掉，只留颜色和文字变化。
自动刷新后新出现的卡淡入，状态变化的卡只换一次颜色，不叠加第二套动画。

## 常见走错

- 第一层直接摆任务卡、图表、额度 —— 回到「一句话 + 几行」，点开再看。
- 给状态加第二支颜色 —— 只调黄绿的饱和度，用符号或文字补意思。
- 同一个对象在页面里手抄一份 —— 去 `components.ts` 找函数；没有就先抽，见第二层清单。
- 把表单摊在设置第一层 —— 收进展开后的第二层，或者抽屉。
- 拿旧的橙 / 红 / 蓝 / 绿表示状态 —— 044 v3 已经不用这套。
- 动效弹一下、转一圈 —— 删掉；体感是顺手，不是表演。
- 数字不带口径 —— 补「今日」「近 30 天」「当前窗口」还是「这次运行」。
