# 常见问题

按「你想知道什么」分组。每条尽量一两句说完；需要细节的，括号里指到 [USAGE.md](USAGE.md) 的哪一节。

## 一、这是什么、适合谁

**1. 这到底是个什么东西？**
一个放在你自己服务器（或家里电脑）上的网页控制台：把交给 AI 写代码的任务集中到一个看板，危险动作停下来等你在网页上点批准，同时看 Token 用量和账号余额。

**2. 它和 Claude Code、Codex 是什么关系？**
不是替代品。它管的是「派活、盯进度、批危险动作、记账」，真正干活的还是 Claude Code 这类命令行工具（USAGE §7）。

**3. 是不是一个代理池 / 多人共用的服务？**
都不是。它是**单用户**的：一个令牌、一个密码、一份数据，默认只绑本机，给别人用请另外部署一份。

**4. 一台电脑够不够？要不要 GitHub、Docker、Claude 账号？**
一台够（工作台和执行器可以同一台）。Docker 建议有（USAGE §1）。GitHub 可选，只影响「用 Issue 派活」和日报（USAGE §8、§9）。Claude 账号不是必须的，执行器也能接别的模型接口（USAGE §7）。

## 二、要花多少钱

**5. 这个工具本身收费吗？**
不收费，源码公开、非商用免费（见最后一组）。

**6. 那钱花在哪？**
花在模型接口上，按用量付费。工作台只记账，不替你付钱（USAGE §6）。

**7. 怎么知道花了多少？**
侧栏左下角点「额度」看账号余额和窗口；「记录」看任务和 token，「剧组」里看每个执行者。填了单价的账号会算得更准（USAGE §6）。

**8. 怎么防止它自己烧钱？**
先设执行者的「每日 token 上限」、单任务 token 和时长上限；不想让新任务自己开跑，就关掉该执行者的「自动执行」。每日上限管新领取，单任务预算管已经在跑的活（USAGE §5）。

**9. 试用先充多少合适？**
先充最小额度，跑通一两个小任务看看账对不对，再决定加不加。别一上来充一大笔。

## 三、安装

**10. 支持哪些系统？**
主要在 **Windows + Docker Desktop** 上做真机验收，Windows 和 Linux 的自动测试都跑过；Mac、Linux 桌面上的装机和日常使用还没完整验过。没 Docker 也能用 Node 跑工作台，只有容器沙箱需要 Docker。

**11. Node 要什么版本？**
22.18 或更新。太旧会报 `Bad option`（USAGE §13）。

**12. 3200 端口被占了怎么办？**
直接用 Node 跑，就改 `.env` 的 `PORT` 后重启；Docker 部署则改 compose 的宿主端口映射（保留容器端口 3200）再重建。两种都要用新端口打开，执行器连接地址也要跟着改。

**13. Docker 拉不到镜像怎么办？**
先确认网络能到镜像源；公司网络或代理环境下给 Docker 配代理，或者换一台机器构建好再拷过去。

**14. 一定要装 Claude Code 命令行吗？**
用 Claude Code + 模型接口的执行器时要装；WorkBuddy 和 dsh 则要装各自的命令行工具。只当看板和待办用，不装也能用（USAGE §7）。

**15. 能让 AI 帮我装吗？**
能。把 [AGENT-INSTALL.md](AGENT-INSTALL.md) 丢给你的 coding agent，它会照着走一遍；装完对着网页上的「开始使用」清单逐项打勾。

## 四、安全

**16. 为什么有令牌和密码两把？**
密码是给人登录网页的，令牌是给脚本和 agent 调接口的（`Authorization: Bearer`）。网页会话能批审批、改规则，脚本令牌不能；令牌仍能访问它获准的任务和数据，泄露了也要换（USAGE §12）。

**17. 为什么不能开到公网？**
它设计成单用户、无 HTTPS、无防爆破之外的保护。开公网等于把「能批准任意命令」的入口挂到互联网上。手机要用就走 Tailscale（USAGE §11）。

**18. 手机怎么安全地用？**
两种，其他的都不建议：

- **在家**：Docker 部署在 `.env` 写 `WB_BIND=0.0.0.0`，重建容器；直接用 Node 跑则设 `HOST=0.0.0.0` 后重启。手机打开 `http://电脑的局域网IP:3200`。局域网里是明文，别在公司或咖啡店的网络里这么开。
- **出门**：电脑和手机装同一个 Tailscale，电脑上跑 `tailscale serve 3200`，手机打开 `https://电脑名.xxx.ts.net`。别用 funnel，也别填 localhost。

为什么默认手机打不开？024 起默认只绑本机，只有这台电脑能开。这是故意的：一装上就被同网段所有设备打开、再被路由器端口转发一下，就上网了——所以默认关着，别开。

**19. 备份文件为什么当敏感文件？**
备份是这个库的完整副本，等于把「你干过什么、接过哪些账号」全带走。备份里已经删掉登录会话和密码指纹，但仍应放在只有你能访问的目录。

**20. API key 放哪？**
干活用的模型 key 和 GitHub 令牌放执行器自己的配置或环境变量；工作台 `.env` 只填它需要的接入配置（例如可选余额读取器）。不进仓库、不进截图、不发聊天，泄露过就换新。

**21. 换密码会怎样？**
下次启动会清掉所有已登录的浏览器（这正是你想要的），脚本用的令牌不受影响。

**22. 怀疑泄露了怎么办？**
三步：换 `WB_PASSWORD` 和 `WB_TOKEN`、撤销并重建泄露的接口 key、看「记录 › 审计日志」里有没有陌生操作（USAGE §12）。

## 五、日常使用

**23. 任务一直「排队」不动？**
先看执行器在线吗、任务点过「开始」吗、执行者和账号槽可用吗。详情会写排队原因；「排队等沙箱名额」就是等前面的容器收工（USAGE §13）。

**24. 「执行器没开」但它明明在跑？**
心跳没到。看执行器窗口的日志，`curl` 一下 `/api/health`，确认它连的是同一个地址、同一个容器网络（USAGE §13）。

**25. 为什么一个任务要我批两次？**
合并是让改动进本地 main，推送是让改动出门，两道分开。普通任务只改 docs/ 时合并可按设置自动过；沙箱补丁仍要批，只读且没改文件的任务不用合并（USAGE §3）。

**26. 批错了怎么办？**
立刻在「记录 › 审计日志」看那条动作干了什么；如果是推送，远端已经变了，需要你自己回退。批之前看一眼改动，比事后回退省事。

**27. 「打回修改」的意见怎么写？**
写成 agent 能照做的一句话：「先把测试补上再推」而不是「再改改」。意见会原样发给它（USAGE §3）。

**28. 任务卡在「运行中」很久？**
超过单任务时长两倍没动静会标「可能卡住了」。多半是执行器进程没了（关窗口、睡眠），在详情里点「标记失败」再重来（USAGE §13）。

**29. 改了称呼但页面还有旧名字？**
浏览器缓存，强制刷新（Ctrl/Cmd + Shift + R）。

## 六、沙箱（Docker）

开了沙箱以后，任务在一个一次性容器里跑，出网只走白名单。这三条是 Windows 上真机踩过的坑。

**30. 白名单里的站点也打不开，403，原因里提到 fake-ip？**
宿主开着 Clash 一类的代理、并且开了 fake-ip：所有域名都被解析成 `198.18.x.x`，这段是保留地址，沙箱默认按内网拦。在执行器配置 `~/.ai-workbench-runner.json` 顶层加 `"sandboxFakeIp": true`，重启执行器。这个开关只对白名单里的域名生效，别的私网目标照样拦。

**31. `npm run sandbox:build` 打镜像时 Debian 源报 502？**
换镜像源重打：`npm run sandbox:build -- --apt-mirror mirrors.tuna.tsinghua.edu.cn`（只换主机名，apt 的签名校验还在）。Docker Hub 也拉不动，再加 `--base` 换一个基础镜像源。

**32. 开了沙箱以后，WorkBuddy、DeepSeek Harness、用订阅登录（账号槽）的任务全失败？**
第一版沙箱只支持 Claude Code + API Key 后端。去掉全局的 sandbox，只给 `pool` 这类执行者写 `"sandbox": "docker"`；其余执行者不用写这一项。sandboxFakeIp 仍可留在全局。进不去沙箱不会悄悄退回宿主上跑，所以配置不匹配时任务直接失败。

## 七、出问题怎么反馈

**33. 遇到问题该给你什么？**
运行 `npm run diagnose`，把输出整段发过来——它已经自动把密钥、路径、邮箱打码了。

**34. 什么不要发？**
`.env`、`~/.ai-workbench-runner.json`、备份的 `.db` 文件、任何截图里的 key。要发就发 `diagnose` 的输出。

## 九、还没做的（已知局限）

**41. 现在还缺什么？**
Claude Code、WorkBuddy（codebuddy）、dsh 都已有接入，后两者仍有只读或真实审批验收的限制；Codex CLI 的自动执行审批 hook 还没做。也没有内置 HTTPS、多用户权限、行业包或多调度。完整边界看 README，别把路线图当已交付功能。

**42. 支持 Windows 以外的机器自动干活吗？**
脚本是跨平台的，Windows 和 Linux 自动测试都跑过；**真机安装、账号登录和长期使用主要在 Windows 验过**，不能把测试通过当成 Mac / Linux 桌面也全部验过。

**43. 数据存在哪？**
一个 SQLite 文件，在 `data/` 里（容器里在 `/data`）。备份就是复制这个文件（USAGE §10）。
